# Penetration Tester

## Role overview
A penetration tester performs authorized, scoped security tests to identify weaknesses, validate their impact, and communicate practical remediation advice. Testing without explicit permission and a defined scope is not appropriate.

## Core skills
- Networking, DNS, HTTP/HTTPS, ports, routing, and Linux.
- Web application concepts: requests, responses, sessions, cookies, authentication, and access control.
- Common vulnerability classes and safe validation methods.
- Tools such as Burp Suite Community Edition and browser developer tools, used only in authorized labs.
- Evidence collection, reproducible steps, risk explanation, and professional report writing.
- Scripting basics in Python or shell to support repeatable tasks.

## Beginner learning roadmap
1. Learn TCP/IP, DNS, HTTP, and Linux fundamentals.
2. Understand how browsers and web applications exchange requests and responses.
3. Practice in intentionally vulnerable local applications or training platforms where testing is authorized.
4. Learn to document a finding with scope, evidence, impact, and remediation.
5. Repeat tests after fixes to understand verification.

## Beginner projects
- Set up a local vulnerable training app and document one low-risk issue in the lab.
- Inspect HTTP requests in a local test environment and explain each field.
- Create a report template with summary, affected component, reproduction steps, impact, and remediation.

## Certifications and credentials
Practical certifications can be expensive and may have prerequisites. Build foundational skills and a small legal lab portfolio first, then compare current employer requirements and official certification pages. Do not assume a certificate guarantees employment.

## Example entry-level job keywords
Junior Penetration Tester, Security Testing Intern, Vulnerability Assessment Analyst, and Application Security Intern. Employers differ on experience and certification expectations.

## Safety boundary
Only test assets you own or have explicit written permission to assess, and stay within the agreed scope. Never use this learning guide as permission to scan or exploit third-party systems.
